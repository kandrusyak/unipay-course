# С чего начать

Это обычный Python-проект. Сеть, Docker, база данных и разработка API не входят в ваши задания.
Работайте только с уже выданной папкой `labs/labNN`. Следующая папка самостоятельна:
переносить в неё незавершённый код предыдущей работы не требуется.

## Первый запуск

Команды установки Python-окружения приведены в README.md. После установки pytest запустите
из корня проекта `python check.py lab01`. Затем откройте `labs/lab01/TASK.md`.
Не начинайте с чтения всех тестов и служебных файлов: сначала цель, обязательная задача и порядок работы.

На ЛР1 и ЛР4 стартовые тесты уже зелёные: нужно изменить устройство кода, а не искать скрытый баг.
На остальных работах часть проверок специально падает. Их исходный список — STARTER-STATE.md.
Ошибка установки или импорта — не учебная задача: сообщите преподавателю, не отключайте тесты.

## Что читать в коде

`app/domain/` — объекты: их данные и действия. `app/services/` — координация этих объектов.
`app/services/assembly.py` — место создания зависимостей, изменяемое только с ЛР5.
`app/api.py` — готовые функции входа. `app/support/` — готовые вспомогательные типы и проверки.
Точный список разрешённых файлов всегда указан в TASK.md.

`self` — экземпляр, у которого вызван метод. `@property` позволяет читать значение как поле:
на ранних работах такие свойства уже даны. `Money` содержит сумму и валюту; не заменяйте Decimal
на float. `ABC` — основа абстрактного класса, `@abstractmethod` отмечает метод, который
нужно реализовать в наследнике; они понадобятся с ЛР3. `dataclass(frozen=True)` в готовом коде
создаёт объект с ограничением изменения полей; устройство декоратора объяснять не требуется.
Исключение DomainError сообщает код ошибки. Понятия вводятся по очереди, а не все в первой работе.

## Когда остановиться

Выполните только обязательные изменения текущей работы и запустите её проверки.
Короткое решение нормально: не добавляйте классы и слои ради объёма.
На защите один участник может проследить успешный вызов, другой — объяснить отказ или место расширения.
Преподаватель вправе спросить любого участника о любом участке. Отдельный отчёт и новые тесты не нужны.

Необязательное расширение находится в конце TASK.md и запускается с `--bonus`.
Его отсутствие не мешает сдать основную часть. Полная REFERENCE.md нужна для уточнения типов
и предметных условий; она не требует реализовывать будущие работы заранее.
