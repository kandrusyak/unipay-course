# UniPay — практические работы по ООП на Python

Здесь находятся **только открытые преподавателем лабораторные** и файл для их получения.
Решений и преподавательской истории Git здесь нет. Не форкайте этот репозиторий:
каждая пара работает в своём пустом репозитории в аккаунте одного из участников.

## Получить первую работу

Нужен Python **3.13**. Скачайте [unipay.py](https://raw.githubusercontent.com/kandrusyak/unipay-course/main/unipay.py)
(откройте ссылку и сохраните именно файл `.py`, не HTML-страницу GitHub) в корень своего
пустого локального репозитория. Других файлов, кроме `.git` и `unipay.py`, пока быть не должно.
Создавая репозиторий на GitHub, не добавляйте автоматически README и лицензию.

Откройте терминал в этой папке:

```sh
python unipay.py 1 --variant card
```

`card` замените вариантом, назначенным вашей паре. Подтвердите добавление файлов ответом `y`.
Вариант сохраняется один раз; следующие работы:

```sh
python unipay.py --list
python unipay.py 2
```

Неопубликованный номер скачать нельзя. Скрипт можно вызвать без аргументов:
он спросит вариант и номер. Запустить из Downloads с указанием папки:
`python unipay.py 1 --variant card --target "ПУТЬ_К_КЛОНУ"`.
В Windows вместо `python` можно использовать `py -3.13`.

Скрипт скачивает данные по HTTPS без токена GitHub и сторонних библиотек, показывает
список файлов и спрашивает разрешение. Он **не делает commit/push и не запускает код работы**.
Повтор того же номера не сбрасывает ваше решение; конфликт останавливает установку.
Предпросмотр без записи — `--dry-run`, заранее явное подтверждение — `--yes`.
Для позднего номера должны быть получены предыдущие выдачи; **сдавать их ради получения следующей не нужно**.
Не удаляйте `.unipay` или свои решения при ошибке — обратитесь к преподавателю.

## Работать над заданием

После первой загрузки прочитайте `START_HERE.md` и `labs/lab01/TASK.md`. Создайте окружение
по README вашего репозитория, затем:

```sh
python -m pip install -r requirements.txt
python check.py lab01
```

Тесты предоставлены преподавателем. На ЛР1/ЛР4 они зелёные изначально, но рефакторинг обязателен.
На остальных работах начальные ошибки описаны в задании. Бонус добровольный, ИИ разрешён,
но оба участника должны понимать решение. Нужны содержательные коммиты обоих, PR, merge
и короткая защита. Сеть, БД и Docker в вашем коде не требуются.

## Варианты

1 Customer · 2 Card · 3 Account · 4 Merchant · 5 Authorization · 6 Limits · 7 Fraud ·
8 FX · 9 Ledger · 10 Notification · 11 Audit · 12 Reporting · 13 Clearing · 14 Settlement.

В команде используйте английское имя в нижнем регистре. Доступные номера выводит `--list`.
Файлы получайте только отсюда или от преподавателя; контрольная сумма не является цифровой
подписью и не делает неизвестный Python-код безопасным. При ошибке TLS не отключайте проверку сертификатов.
