# UniPay — практические работы по ООП на Python

Здесь находятся загрузчик и только открытые преподавателем работы. Создайте **свой пустой
репозиторий** в аккаунте одного из участников пары и пригласите второго участника.
Не делайте fork этого каталога: для своей работы достаточно одного файла.

## Скачать и получить работу

Скачайте [unipay.py](https://raw.githubusercontent.com/kandrusyak/unipay-course/main/unipay.py)
(сохраните ссылку как файл, не HTML-страницу) и положите в корень локального клона своей пары.
Нужен Python 3.13; загрузчик использует только стандартную библиотеку, GitHub-токен не нужен.

В терминале **из этой папки**, например для варианта Card:

```sh
python unipay.py --list
python unipay.py 1 --variant card
```

Вариант назначает преподаватель. Можно указать его номер, например `--variant 2` вместо `card`.
Загрузчик покажет, что добавит, и спросит подтверждение. Для предварительного просмотра
без записи: `python unipay.py 1 --variant card --dry-run`.

После открытия следующей работы вариант уже сохранён:

```sh
python unipay.py 2
```

Нет ручных архивов и распаковки. Загрузчик сам получает данные и проверяет их перед добавлением.
Неопубликованный номер получить нельзя: будущих пакетов в публичном репозитории нет.
Получать работы нужно по порядку, **сдавать предыдущую перед получением следующей не требуется**.

## После получения

```sh
python -m venv .venv
```

Windows PowerShell: `.\.venv\Scripts\Activate.ps1`; Linux: `source .venv/bin/activate`.
Далее:

```sh
python -m pip install -r requirements.txt
python check.py lab01
```

Откройте `labs/lab01/TASK.md`. В ЛР1 и ЛР4 начальные тесты зелёные: необходимо выполнить
указанный рефакторинг, а не просто показать PASS. В остальных работах ожидаемые исходные
падения перечислены в `STARTER-STATE.md`. Для сдачи все обязательные проверки должны пройти.
Бонус необязателен, ИИ разрешён; оба участника должны понимать своё решение.

`git status`, commit, push и PR выполняете сами. Новую выдачу удобно добавлять в ветке
`issue/lab02`, решение — в отдельной ветке лабораторной. Красные проверки заготовки допустимы
для PR выдачи, но не для сдачи решения. У загрузчика нет автоматических Git-операций.

## Сохранность работы

Повтор того же номера **не перезаписывает решение**. Другая редакция уже выданной работы,
чужой вариант, изменённый запускатель или конфликт файлов приводят к остановке.
Не удаляйте `.unipay/` и собственный код ради обхода ошибки: обратитесь к преподавателю.
Загрузчик не обновляет сам себя, не запускает полученный код и не устанавливает библиотеки.
SHA-256 защищает от повреждения и несогласованности данных, но не является подписью автора.
Скачивайте Python-файл только по указанной ссылке и не отключайте проверку HTTPS.

Первая выдача требует пустого клона: допускаются только `.git` и выполняющийся `unipay.py`.
Не создавайте автоматически README/лицензию при создании репозитория; окружение создайте
после первой выдачи. Также можно держать загрузчик вне клона:
`python ../unipay.py 1 --variant card --target .`.

При недоступности GitHub или ошибке контрольных сумм работа не устанавливается.
Для Windows вместо `python` при необходимости используйте `py -3.13`.
`--yes` подтверждает добавление для неинтерактивного запуска; не отменяет защиту файлов.

В этом публичном репозитории нет преподавательских эталонов, закрытых будущих заготовок,
списков студентов и истории преподавательского репозитория.
