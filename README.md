# UniPay — практические работы по ООП на Python

Работы выполняются в парах. Каждая пара дорабатывает свой сервис учебной платёжной системы. Вариант назначает преподаватель.

Для работы нужны **Python 3.10 или 3.13**, Git и аккаунт GitHub.

## Подготовка

Один из участников создаёт пустой репозиторий в своём аккаунте GitHub, добавляет второго участника и предоставляет доступ преподавателю. При создании не добавляйте README, `.gitignore` и лицензию. Клонируйте репозиторий на компьютер — **fork этого репозитория делать не нужно**.

[Скачайте `unipay.py`](https://raw.githubusercontent.com/kandrusyak/unipay-course/main/unipay.py) и сохраните его в корень своего локального репозитория. Сохранить нужно файл `.py`, не HTML-страницу. Перед первой загрузкой в папке должны быть только `.git` и `unipay.py`; окружение `.venv` создайте после получения работы.

## Получение лабораторных

Откройте терминал в папке своего репозитория и выполните:

```sh
python unipay.py 1 --variant card
```

Вместо `card` укажите название своего варианта в нижнем регистре, например `account` или `notification`. Подтвердите добавление файлов ответом `y`.

Вариант сохраняется. Посмотреть доступные номера и получить следующую работу:

```sh
python unipay.py --list
python unipay.py 2
```

Номера открываются постепенно. Получайте их по порядку; сдавать предыдущую работу ради скачивания следующей не нужно. Повторная загрузка того же номера не перезаписывает решение. При конфликте не удаляйте свои файлы или папку `.unipay` — обратитесь к преподавателю.

В Windows вместо `python` можно использовать `py -3.10` или `py -3.13`.

## Выполнение работы

Прочитайте `START_HERE.md` и задание в `labs/lab01/TASK.md`. Настройте Python-окружение по README в своём репозитории, затем установите зависимости и запустите проверки:

```sh
python -m pip install -r requirements.txt
python check.py lab01
```

Для другой работы замените `lab01` её номером, например `lab02`. Меняйте только разрешённые в задании файлы; API и готовые тесты не редактируйте.

В ЛР1 и ЛР4 тесты проходят изначально, но указанный рефакторинг всё равно обязателен. В остальных работах начальные ошибки перечислены в `STARTER-STATE.md` соответствующей папки.

Бонус необязателен. Его проверка: `python check.py lab01 --bonus`.

## Сдача

Работайте в отдельной ветке. Оба участника вносят содержательные коммиты и объединяют изменения в `main` своего репозитория.

Для сдачи нужны проходящие обязательные тесты, выполненные изменения из задания и короткая защита обоих участников.
